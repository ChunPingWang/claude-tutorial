# 01 · 快速上手

## 1.1 安裝與啟動

```bash
# npm（最通用）
npm install -g @anthropic-ai/claude-code

# 或原生安裝腳本（macOS / Linux）
curl -fsSL https://claude.ai/install.sh | bash

claude --version     # 確認版本
claude               # 在目前目錄啟動互動 session
```

第一次啟動會要你登入（Claude 帳號訂閱或 API key）。登入狀態存在 `~/.claude.json`。

Claude Code 也有其他介面：桌面 App（Mac/Windows）、網頁版 `claude.ai/code`、
VS Code 與 JetBrains 外掛。設定檔（`~/.claude/`）是共用的。

## 1.2 三種執行模式

| 模式 | 指令 | 用途 |
| --- | --- | --- |
| 互動 | `claude` | 日常開發，最常用 |
| 續接 | `claude -c` / `claude --resume` | 接續上一個 / 挑一個舊 session |
| 無頭 | `claude -p "prompt"` | 腳本、CI、pipe。輸出到 stdout |

無頭模式範例：

```bash
# 把 git diff 丟給 Claude 產生 commit message
git diff --staged | claude -p "根據這份 diff 寫一則 commit message，只輸出訊息本身"

# JSON 輸出，方便程式解析
claude -p "列出這個 repo 的技術棧" --output-format json
```

## 1.3 第一次對話該說什麼

Claude Code 預設**不會**先讀完整個 repo（那會炸掉 context）。它是邊做邊找。所以：

**好的開場**
```
先看一下 src/payment/ 這個模組，跟我解釋 retry 的邏輯寫在哪、怎麼運作
```

**不好的開場**
```
幫我優化這個專案
```

原則：**給範圍、給目標、給驗收標準**。

三段式提問模板：

```
【背景】我們的 checkout API 在高併發時會重複扣款。
【範圍】相關程式在 src/payment/ 和 src/queue/。
【要求】先只做調查，找出可能的 race condition，列成清單給我，先不要改任何檔案。
```

最後那句「先不要改」非常有用——先讓它讀懂，再讓它動手。

## 1.4 必知的快捷鍵

| 按鍵 | 作用 |
| --- | --- |
| `Shift+Tab` | 循環切換權限模式（一般 → 自動接受編輯 → 計畫模式） |
| `Esc` | 中斷 Claude 目前的動作（不會結束 session） |
| `Esc` `Esc` | 開啟訊息歷史，可跳回之前某個時間點 |
| `↑` / `↓` | 翻閱你輸入過的 prompt 歷史 |
| `Ctrl+R` | 展開/收合完整的工具輸出 |
| `!` 開頭 | 直接在 session 內跑 shell 指令，例如 `!git status` |
| `@` 開頭 | 引用檔案或子代理，例如 `@src/main.ts` |
| `/` 開頭 | 呼叫指令 / Skill |
| `#` 開頭 | 快速把一句話寫進記憶 |
| `Ctrl+C` ×2 | 離開 |

> `!` 這招很重要：需要你親自跑的互動式指令（`gcloud auth login`、`vim`），
> 直接在輸入框打 `! gcloud auth login`，輸出會進到對話裡讓 Claude 看到。

## 1.5 十個最常用的內建指令

| 指令 | 用途 |
| --- | --- |
| `/init` | 分析 codebase 並產生 `CLAUDE.md`（已存在則提出改進建議） |
| `/context` | **最重要的除錯指令**：看目前 context 載入了哪些記憶檔、佔多少 token |
| `/memory` | 瀏覽 / 編輯所有 CLAUDE.md 與 auto memory 檔案 |
| `/config` | 開設定介面；也可 `/config key=value` 直接設 |
| `/status` | 目前模型、設定來源、帳號、連線狀態 |
| `/doctor` | 健檢：找出無效設定、過大的 CLAUDE.md |
| `/permissions` | 檢視與編輯權限規則 |
| `/mcp` | MCP server 狀態與登入 |
| `/plugin` | 外掛管理器（安裝、市集、錯誤分頁） |
| `/compact` | 手動壓縮 context（可加指示：`/compact 保留 API 設計討論`） |
| `/clear` | 清空對話重新開始（設定檔不受影響） |
| `/rewind` | 回到之前的 checkpoint，可還原檔案 |

輸入 `/` 會列出全部（含你自己的 Skills）。

## 1.6 權限模式

按 `Shift+Tab` 循環切換，右下角會顯示目前模式：

| 模式 | 行為 | 什麼時候用 |
| --- | --- | --- |
| **default** | 每個會改東西的動作都問你 | 平常 |
| **acceptEdits** | 檔案編輯自動放行，其他仍要問 | 你已經確認方向、要它連續改多檔 |
| **plan** | **唯讀**。只能看、不能改，最後產出計畫給你核准 | 大改動之前，強烈建議先跑一次 |
| **bypassPermissions** | 全部放行 | 只在容器/沙箱裡用。危險 |

**計畫模式（plan mode）是新手最該養成的習慣**：先讓 Claude 在唯讀狀態下把 repo 讀懂、
寫出實作計畫，你審過再放它動手。避免它一路改到底才發現方向錯了。

## 1.7 一個完整的小例子

```
$ cd ~/work/my-api
$ claude

> /init
  … Claude 讀完 repo，寫出 CLAUDE.md，你檢查後接受

> (按 Shift+Tab 兩次進入 plan mode)
> 我要幫 /users 端點加上分頁功能，先給我實作計畫

  … Claude 讀相關檔案，產出計畫，你按 Enter 核准

> (自動切回一般模式，Claude 開始實作)

> 跑一下測試
  … Claude 執行 npm test，看到失敗會自己修

> 幫我 commit，訊息用繁體中文
```

## 1.8 常見新手錯誤

| 症狀 | 原因 | 解法 |
| --- | --- | --- |
| Claude 好像沒看到我的規則 | CLAUDE.md 沒被載入 | 跑 `/context` 確認 **Memory files** 有列到它 |
| 一直跳權限確認 | 沒設白名單 | `/permissions` 加 allow 規則，或跑 `/fewer-permission-prompts` |
| 講過的事情它忘了 | context 被壓縮了 | 把它寫進 CLAUDE.md 或用 `#` 存進記憶 |
| 它改了不該改的檔案 | 沒給範圍 | 用 plan mode，或在 CLAUDE.md 寫明禁區 |
| 回答很慢很發散 | 一次要求太多 | 拆成「調查 → 計畫 → 實作 → 驗證」四段 |
