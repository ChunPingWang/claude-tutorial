# 11 · 多代理與平行執行

第 05 章的子代理只是**四種平行方式之一**。這章補齊另外三種，以及它們共用的支援機制。

差別的核心是一句話：**誰握著那份計畫？**

---

## 11.1 四種方式怎麼選

| 方式 | 給你什麼 | 何時用 |
| --- | --- | --- |
| **[子代理](05-Subagents-子代理.md)** | 一個 session 內委派出去的工人，用自己的 context 做完再回報摘要 | 側支任務會用搜尋結果／日誌／檔案內容灌爆主對話 |
| **Agent view** | 一個畫面派工與監看背景 session，`claude agents` 開啟 | 有好幾個獨立任務想丟出去，只在需要你時才介入 |
| **Agent teams** | 多個互相協調的 session，共享任務清單、彼此傳訊，由 lead 統籌 | 要 Claude 自己拆工作、分配、並讓工人互相同步 |
| **Dynamic workflows** | 一個腳本跑大量子代理並交叉驗證結果 | 工作大到一輪一輪協調不完，或需要多次驗證 |

決策三問：

**1. 誰協調？**
- Claude 在同一場對話裡委派並收攏結果 → **子代理**
- 你自己丟出獨立任務，之後再回來看 → **Agent view**
- Claude 規劃、分派、監督一群工人 → **Agent teams**
- 由**腳本**握著計畫，而不是 Claude 的逐輪判斷 → **Dynamic workflows**

**2. 工人之間需要對話嗎？**
子代理只向呼叫它的對話回報，彼此看不見。teammates 可以直接互傳訊息並共用任務清單。
獨立 session 之間則用 [cross-session messaging](#115-三個支援機制)。

**3. 會不會動到同一批檔案？**
會的話要隔離。子代理與你自己開的 session 都可以各配一個 [worktree](05-Subagents-子代理.md#58-worktree-隔離)；
**但 agent teams 不會替 teammates 做隔離**——必須靠切分工作，讓每個人負責不同檔案。

> ⚠️ 三個成熟度標籤先講清楚：
> **子代理**與 **workflows** 是正式功能；
> **Agent view** 是 research preview；
> **Agent teams** 是 experimental 且**預設關閉**。
> 後兩者的介面與行為還會變，用在教學或團隊流程前請自行評估。

## 11.2 Agent view：背景 session 的派工台

`claude agents` 開啟一個畫面，列出所有背景 session，依狀態分組
（需要輸入 / 執行中 / 已完成）。

### 基本操作

```bash
claude agents            # 開啟
```

在裡面直接打任務描述按 Enter，就會開一個新的背景 session：

```
investigate the flaky SettingsChangeDetector test
```

| 按鍵 | 動作 |
| --- | --- |
| `↑` `↓` | 選擇 |
| `Space` | 開 peek 面板，看最新輸出或它的提問，不用進去 |
| `Enter` / `→` | 完整接上這個 session |
| `←`（輸入框空白時） | 脫離，回到 agent view |
| `Ctrl+T` | 釘選（保持執行） |
| `Ctrl+R` | 改名 |
| `Ctrl+X` | 停止（再按一次刪除） |
| `?` | 全部快捷鍵 |

### 從 shell 派工

```bash
claude --bg "investigate the flaky test"
claude --bg --name "flaky-fix" "investigate the flaky test"
claude --agent code-reviewer --bg "address review comments on PR 1234"
claude --bg --exec 'pytest -x'          # 只跑一個 shell 指令
```

在 agent view 裡用 `!` 前綴等同 `--exec`：`! pytest -x`

### 從既有 session 丟到背景

```
/bg <接下來的指示>
```

或在空輸入框按 `←`，把目前 session 丟到背景並開啟 agent view。

### 檔案編輯自動隔離

**背景 session 會自動用 worktree 隔離**（這點跟子代理不同）：

1. session 從你的工作目錄啟動
2. **在動手改檔案之前**，移到 `.claude/worktrees/<id>/`
3. 多個 session 可以讀同一份 checkout，但各自寫進自己的 worktree

要關掉：

```json
{ "worktree": { "bgIsolation": "none" } }
```

> ⚠️ agent view 建立的 worktree 會**隨 session 一起刪除**。有想留的改動，先 commit。

### 管理指令

```bash
claude agents --cwd <path>     # 限定目錄
claude agents --json           # 以 JSON 列出
claude attach <id>
claude logs <id>
claude stop <id>
claude rm <id>
claude respawn <id>
```

派工預設值：

```bash
claude agents --permission-mode plan --model opus --effort high
```

### 關閉

```json
{ "disableAgentView": true }
```

或環境變數 `CLAUDE_CODE_DISABLE_AGENT_VIEW=1`。

> 關掉 agent view 會改變 fork 相關指令的名稱，見 [11.6](#116-fork--subtask--背景-bash-的差別)。

## 11.3 Agent teams：lead 與 teammates

**experimental，預設關閉。**

### 啟用

```json
// settings.json
{ "env": { "CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS": "1" } }
```

沒設這個變數時，session 啟動不會建立 team、不寫 team 目錄，Claude 也不會生出 teammate。

### 跟子代理的差別

| | 子代理 | Teammates |
| --- | --- | --- |
| context | 自己的，結果回傳給呼叫者 | 自己的，完全獨立 |
| 溝通 | 只回報給主代理 | **彼此直接傳訊** |
| 協調 | 主代理管理全部 | 自我協調 + 共享任務清單 |
| 適合 | 只在乎結果的聚焦任務 | 需要討論與互相挑戰的複雜工作 |
| token | 較低（結果被摘要回主 context） | **較高（每個都是完整的 Claude 實例）** |

### 開一個 team

啟用後直接用自然語言描述：

```
我在設計一個追蹤 codebase 裡 TODO 註解的 CLI 工具。
開三個 teammate 從不同角度探討：一個負責 UX、一個負責技術架構、
一個當唱反調的魔鬼代言人。
```

lead 會建立共享任務清單、生出 teammates、最後統整結論。
teammates 列在輸入框下方的 agent panel：`↑↓` 選、`Enter` 進去看逐字稿並直接對它下指令、`Esc` 中斷它。

### ⚠️ 最重要的副作用

**啟用 agent teams 會改變一般的委派行為。**
Claude 本來就會自己替子代理命名（方便之後傳訊給它）；
而在 agent teams 開啟時，**一個被命名的子代理會以 teammate 的身分啟動**——
所以你根本沒要求組隊，team 也可能自己形成。

這會打斷「等子代理回傳結果」的流程：

- 子代理：完成時 Claude 會**收到它的結果**
- teammate：只送出一則「我閒置了」的通知，**不帶輸出**

要恢復原本行為，把變數設成 `"0"`（存檔即生效，不用重開 session）：

```json
{ "env": { "CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS": "0" } }
```

注意優先序：專案／local／`--settings` 會蓋過使用者設定，managed settings 最後套用。

### 顯示模式

| 值 | 行為 |
| --- | --- |
| `"in-process"`（預設） | 全部在主終端機，用 agent panel 切換 |
| `"auto"` | 已在 tmux 或 iTerm2（裝了 `it2`）時用分割窗格，否則退回 in-process |
| `"tmux"` / `"iterm2"` | 明確指定分割窗格 |

```json
{ "teammateMode": "auto" }
```

分割窗格在 VS Code 內建終端機、Windows Terminal、Ghostty 都**不支援**。

### teammates 拿得到什麼

- ✅ CLAUDE.md、MCP servers、skills（跟一般 session 一樣從專案與使用者設定載入）
- ✅ lead 給它的那段 spawn prompt
- ❌ **lead 的對話歷史不會帶過去**

所以 spawn prompt 要寫得夠完整：

```
開一個 security reviewer teammate，prompt 寫：「檢查 src/auth/ 的安全漏洞，
重點看 token 處理、session 管理、input validation。這個 app 用 JWT 存在
httpOnly cookie。回報問題並標註嚴重度。」
```

可以指定用哪個子代理定義當 teammate 的角色：

```
用 security-reviewer 這個 agent type 開一個 teammate 稽核 auth 模組
```

它會沿用該定義的 `tools` 與 `model`，定義的內文**附加**到 system prompt（不是取代）。
但 `skills` 與 `mcpServers` 兩個 frontmatter 欄位在這個模式下**不生效**。

### 要求先出計畫

```
開一個 architect teammate 重構認證模組。動手前要先經過計畫核准。
```

teammate 會在唯讀的 plan mode 工作，計畫送給 lead 審。lead 是**自主決定**的，
要影響它就在 prompt 裡給準則：「只核准含測試涵蓋的計畫」「拒絕修改資料庫 schema 的計畫」。

### 用 hooks 設品質關卡

| Hook | 時機 | 退出碼 2 的效果 |
| --- | --- | --- |
| `TeammateIdle` | teammate 即將閒置 | 送回饋並讓它繼續工作 |
| `TaskCreated` | 任務建立時 | 阻止建立並回饋 |
| `TaskCompleted` | 任務標記完成時 | 阻止完成並回饋 |

### 存在哪

```
~/.claude/teams/{team-name}/config.json        session 結束即刪
~/.claude/teams/{team-name}/inboxes/{agent}.json   信箱
~/.claude/tasks/{team-name}/                   任務清單，會保留給續接的 session
```

team 名稱是 `session-` 加 session ID 的前八碼，**自動產生**。
`config.json` 存的是執行期狀態，不要手改，下次狀態更新就被覆蓋。
專案裡的 `.claude/teams/teams.json` **不是**設定檔，Claude 只把它當普通檔案。

### 實務建議

- **3–5 個 teammate** 起步。15 個獨立任務也是先用 3 個。三個專注的通常勝過五個發散的
- **從研究與 review 開始**：審 PR、調查 bug、研究套件——邊界清楚又不用寫程式
- **切分檔案所有權**：teammates 沒有 worktree 隔離，兩個人改同一個檔案就是互相覆蓋
- **先預先核准常用權限**：teammate 的權限提示會冒到 lead 這裡，很吵
- **盯著並導正**：放著跑太久，浪費的工作量也越大

### 已知限制

- in-process teammates **無法隨 `/resume`、`/rewind` 還原**——resume 後 lead 可能去找不存在的 teammate，這時叫它重開
- 任務狀態會延遲（teammate 忘記標完成，卡住相依任務）
- 關閉很慢（要等當前請求或工具呼叫結束）
- **一個 session 只有一個 team**，不能建多個具名 team，也不能跨 session 共用
- **不能巢狀**：teammate 不能再生 teammate
- lead 固定是主 session，不能轉移
- 權限在 spawn 時就定了，之後只能個別調整

## 11.4 Dynamic workflows：把計畫寫成腳本

需 v2.1.154+，付費方案可用（Pro 要在 `/config` 的 Dynamic workflows 那列開啟）。

一個 workflow 是**由 Claude 撰寫、runtime 在背景執行的 JavaScript 腳本**，用來大規模編排子代理。

### 為什麼不是子代理就好

| | 子代理 / Skills / Agent teams | Workflows |
| --- | --- | --- |
| 誰決定下一步 | Claude 逐輪判斷 | **腳本** |
| 中間結果放哪 | Claude 的 context window | **腳本變數** |
| 可重複的是 | 工人定義 / 指示 | **編排本身** |
| 規模 | 每輪幾個 | **單次數十到數百個代理** |
| 被中斷時 | 整輪重來 | **可在同一 session 內續跑** |

關鍵差異：workflow 把計畫搬進程式碼，**Claude 的 context 只留最後答案**。
而且它能套用可重複的品質模式——讓獨立代理互相對抗式驗證彼此的發現，或從多個角度各起草一份計畫再互相評比。

### 先跑內建的試試

```
/deep-research Node.js 的 permission model 在 v20 到 v22 之間改了什麼？
```

它會平行做多角度網路搜尋、抓取來源並交叉比對，最後給一份附引用的報告，
沒通過交叉驗證的主張會被過濾掉。

### 讓 Claude 幫你的任務寫一個

在**你自己輸入的 prompt** 裡加關鍵字 `ultracode`，或直接用自然語言講「用一個 workflow 做」：

```
ultracode: 稽核 src/routes/ 底下每個 API 端點有沒有漏掉 auth 檢查
```

```
use a workflow to migrate every component under src/components/
from styled-components to Tailwind, working on each file in its own isolated copy
```

> 關鍵字只在**你親手打的** prompt 裡有效。`-p` 傳入的、排程任務的、webhook 或 PR 留言帶進來的，都不會觸發。
> 打錯了按 `Option+W`（macOS）／`Alt+W` 取消highlight。

要整場 session 都自動編排：

```
/effort ultracode      # = xhigh 推理強度 + 自動 workflow 編排
```

這會讓**每個實質任務**都變成 workflow，token 與時間都顯著增加。回到日常工作記得 `/effort high`。

### 存起來重複用

跑出滿意的結果後：`/workflows` → 選那次執行 → 按 `s`

| 存放位置 | 範圍 |
| --- | --- |
| `.claude/workflows/` | 專案，clone 的人都有 |
| `~/.claude/workflows/` | 個人，所有專案可用 |

之後就是 `/<name>` 指令。同名時**專案的勝出**。
外掛裡放在 `workflows/`，會變成 `/plugin-name:workflow-name`。

可以傳參數，腳本用全域變數 `args` 讀取：

```
Run /triage-issues on issues 1024, 1025, and 1030
```

### 存下來的腳本長這樣

```javascript
export const meta = {
  name: 'audit-routes',
  description: 'Audit every route handler for missing auth checks',
}

const found = await agent('List every .ts file under src/routes/.', {
  schema: { type: 'object', required: ['files'],
            properties: { files: { type: 'array', items: { type: 'string' } } } },
})

const audits = await pipeline(found.files, file =>
  agent(`Audit ${file} for missing authentication checks.`, { label: file }),
)

return audits.filter(Boolean)
```

`agent()` 生一個子代理，`pipeline()` 對清單每個項目各跑一次。
被你中途停掉或遇到無法復原的 API 錯誤時，`agent()` 會回傳 `null`，
所以結尾要 `.filter(Boolean)`。

### 執行時的規則與上限

| 限制 | 原因 |
| --- | --- |
| 執行中不能插話 | 只有代理的權限提示能暫停它。要分段簽核就拆成多個 workflow |
| 腳本本身不能碰檔案系統或 shell | 讀寫與執行都由代理做，腳本只負責協調 |
| 不能 `import()` | 需要函式庫的工作放進代理的任務裡 |
| 同時最多 16 個代理 | 依 CPU 數可能更少 |
| 單次最多 1000 個代理 | 防止失控迴圈 |

> ⚠️ **權限的例外**：workflow 生出的子代理**一律以 `acceptEdits` 模式執行**，
> 並繼承你的工具白名單，**不管你 session 目前是什麼權限模式**。檔案編輯自動核准。
> 不在白名單的 shell 指令、web fetch、MCP 工具仍會中途問你——
> 長時間執行前先把需要的指令加進 `permissions.allow`。

### 控制規模

```
/config workflowSizeGuideline=small
```

| 值 | Claude 會瞄準的代理數 |
| --- | --- |
| `small` | < 5 |
| `medium`（預設） | < 15 |
| `large` | < 50 |
| `unrestricted` | 不設限，依任務決定 |

超過 25 個代理、或預估 token 破 150 萬時，任務面板會出現 `Large workflow` 警告
（只是提醒，不會暫停）。

### 續跑的代價

停掉之後可以續跑，但重播規則很嚴格：

- 停止當下**還在跑**的代理不會被保存，續跑時重來
- **重播依照代理啟動的順序**：快取到第一個沒跑完的就停，在它**之後啟動**的全部重跑，即使早就完成了

所以「把工作切成很多小代理」比「一個長代理」保留更多進度。
續跑只在**同一個 session 內**有效，離開 Claude Code 後下次是從頭開始。

### 關閉

```json
{ "disableWorkflows": true }
```

或 `CLAUDE_CODE_DISABLE_WORKFLOWS=1`，或 `/config` 的開關。

## 11.5 三個支援機制

這三個本身不是「跑代理的方式」，而是支撐上面四種的工具。

### Worktrees

給每個 session 獨立的 git checkout。詳見 [05 章 5.8](05-Subagents-子代理.md#58-worktree-隔離)。
重點回顧：

- 你自己開的 session：`claude --worktree <name>`
- 子代理：`isolation: worktree`
- **背景 session（agent view）：自動隔離**
- **agent teams 的 teammates：不隔離，要自己切分檔案**

### Cross-session messaging

需 v2.1.224+，僅 macOS / Linux（Bedrock 等第三方 provider 不支援）。

讓 Claude 把訊息從你的一個 session 送到另一個。它用 `ListAgents` 找對象、`SendMessage` 送出，
你不需要自己呼叫這些工具：

```
問一下我另一個終端機的 session，migration 跑完了沒
讓 @api-worker 知道 schema migration 完成了
把我們剛才做的事情說明給正在做 payments API 的那個 session
```

看得到誰：`/list-agents`（別名 `/peers`）。涵蓋子代理、本機其他 session（含背景 session）、
你的雲端 session 與其他機器上的 session（後兩者需連上 Remote Control）。

**傳的只有純文字，不會傳對話歷史或檔案。**

安全邊界（重要）：收到的訊息會被明確標示為「來自另一個 Claude session，不是使用者」，因此

- 它**不能代替你核准**任何權限提示
- 它**不能要求改設定**（權限、CLAUDE.md 等）
- 訊息裡的 `/compact` 這類指令只是純文字，**不會被執行**
- 該做的權限提示照樣會跳

控制收訊：

```json
{ "crossSessionInbound": "accept" }   // accept / hold / refuse
{ "isolatePeerMachines": true }       // 出本機前一律要你核准
```

完全關閉送訊：`permissions.deny` 加 `SendMessage` 與 `ListAgents`（不帶括號）。
注意這也會一併關掉對子代理與 teammates 的傳訊，因為是同一個工具。

### `/batch`

一個內建 skill，把一個大改動拆成 **5–30 個 worktree 隔離的子代理，各自開一個 PR**。
它是「子代理 + worktree」的封裝用法，不是另一種協調方式。

## 11.6 fork / subtask / 背景 bash 的差別

這三個名字很像，做的事完全不同：

| | 是什麼 | 帶不帶對話歷史 |
| --- | --- | --- |
| `/subtask` | **forked 子代理**：繼承你完整的對話 context，而非從零開始 | ✅ 全帶 |
| `/fork` | 把**整個 session 複製成一個新的背景 session**，與原本的並行 | ✅ 全帶 |
| 背景 bash 指令 | 只是一個不阻塞對話的 shell 指令，**不會生出代理** | — |
| routine（排程） | 在雲端按排程跑一場 session，不是本機平行 | — |

> ⚠️ 命名陷阱：以上是 **agent view 開啟時**的名稱。
> [把 agent view 關掉](#112-agent-view背景-session-的派工台)後，forked 子代理的指令變成 `/fork`，而 `/subtask` 不存在。

`/fork` 出去的背景 session 會拿到自己的 worktree（除非關掉隔離），
並沿用模型、權限模式與 effort 設定。

Skill 的 `context: fork`（見 [04 章 4.8](04-Skills-技能.md#48-在子代理裡跑context-fork)）
是同一個概念的另一個入口。

## 11.7 檢視執行中的工作

用哪個指令，取決於你用了哪種方式：

| 你在找 | 用這個 |
| --- | --- |
| 背景 session | `claude agents`（agent view，一個畫面看完狀態） |
| 目前 session 的背景工作（含已完成的子代理） | `/tasks` — 可查看、接上、停止 |
| 具名的背景子代理 | 在 `@` 提及的自動完成清單裡，帶狀態顯示 |
| Dynamic workflow 的進度 | `/workflows` — 列出執行中與已完成的、目前階段、完成的代理數 |
| 可以傳訊的對象 | `/list-agents`（`/peers`） |
| 桌面上所有 session | 桌面 App 的平行 session 檢視 |

> ⚠️ `/agents` 從 v2.1.198 起**不再開啟面板**，只會印出子代理檔案位置的提示。
> 要建立或修改子代理，直接改檔案或叫 Claude 做。
> 名字很像但 `/agents`（斜線指令）跟 `claude agents`（shell 指令）是兩回事。

`/workflows` 的進度畫面裡：

| 按鍵 | 動作 |
| --- | --- |
| `Enter` / `→` | 進入階段，再進入單一代理看它的 prompt、工具呼叫與結果 |
| `Esc` / `←` | 退回上一層 |
| `f` | 依狀態過濾代理清單 |
| `p` | 暫停 / 續跑 |
| `x` | 停掉選中的代理，焦點在整個 run 上時停掉整個 workflow |
| `r` | 重啟選中的執行中代理 |
| `s` | 把這次執行的腳本存成指令 |

## 11.8 成本

**平行執行會等比例倍增 token 用量。** 具體來說：

- 10 個平行背景 session ≈ **10 倍**的額度消耗
- 每個 teammate 都是完整的 Claude 實例，各有自己的 context window，成本線性增加
- 一次 workflow 可能比在對話裡做同一件事貴上不少

實務作法：

1. **先跑小的**：一個目錄而不是整個 repo，一個窄問題而不是大問題
2. **先看 `/model`**：平常切小模型的話，大規模執行前確認一下
3. **指定便宜的階段用小模型**：描述任務時直接講「不需要最強模型的階段用小的」
4. **用 `workflowSizeGuideline`** 控制規模
5. **`/workflows` 隨時看每個代理的 token 用量**，不對就停掉——通常不會損失已完成的工作

反過來說：研究、review、新功能開發這類**平行探索真的有價值**的工作，多花的 token 通常划算。
例行性的工作用單一 session 才划算。

## 11.9 一頁總結

```
任務會灌爆主對話
   └→ 子代理（要並行寫檔案再加 isolation: worktree）

有好幾件獨立的事想丟出去，之後再看
   └→ claude agents（背景 session，自動 worktree 隔離）

需要工人之間互相討論、挑戰、共用任務清單
   └→ agent teams（experimental，要先開變數；記得切分檔案所有權）

規模大到一輪一輪協調不完，或需要交叉驗證
   └→ dynamic workflows（ultracode 關鍵字；滿意就存成 /指令）

兩個你自己開的 session 之間要傳個消息
   └→ 直接叫 Claude 傳（cross-session messaging）

一個大改動想拆成很多個 PR
   └→ /batch
```
