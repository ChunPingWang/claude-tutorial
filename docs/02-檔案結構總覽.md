# 02 · 檔案結構總覽

Claude Code 的所有客製化都是**檔案**。這章是整本手冊的地圖。

---

## 2.1 兩棵樹

```
~/.claude/          ← 個人層：跨所有專案生效，不進 git
your-project/       ← 專案層：跟著 repo 走，team 共用
   .claude/
```

規則很簡單：**要分享給隊友的放專案，只有你自己要的放個人。**

---

## 2.2 專案層：`your-project/`

```
your-project/
├── CLAUDE.md                    ✓commit  每個 session 都載入的專案指示
├── CLAUDE.local.md              ✗ignore  你個人的專案偏好（要加進 .gitignore）
├── .mcp.json                    ✓commit  團隊共用的 MCP servers
├── .worktreeinclude             ✓commit  建立 worktree 時要一起複製的 gitignored 檔
│
└── .claude/
    ├── CLAUDE.md                ✓commit  （與根目錄 CLAUDE.md 二擇一，效果相同）
    ├── settings.json            ✓commit  權限、hooks、env、模型預設
    ├── settings.local.json      ✗ignore  你個人的設定覆寫
    │
    ├── rules/                   ✓commit  主題式指示，可用 paths: 限定觸發路徑
    │   ├── testing.md
    │   ├── api-design.md
    │   └── frontend/react.md    （子目錄會被遞迴掃描）
    │
    ├── skills/                  ✓commit  ★ 可用 /name 呼叫的技能
    │   └── security-review/
    │       ├── SKILL.md         　　　　  入口：觸發條件 + 指示
    │       ├── checklist.md     　　　　  需要時才載入的補充資料
    │       └── scripts/scan.py  　　　　  被「執行」而非被讀進 context 的腳本
    │
    ├── commands/                ✓commit  舊版單檔指令（仍可用，新專案請改用 skills/）
    │   └── fix-issue.md         　　　　  → /fix-issue
    │
    ├── agents/                  ✓commit  子代理定義，各自有獨立 context window
    │   └── code-reviewer.md
    │
    ├── workflows/               ✓commit  多代理編排腳本（.js），每個檔案變成一個 /name
    │
    ├── output-styles/           ✓commit  自訂 system prompt 片段
    │
    └── agent-memory/            ✓commit  子代理的持久記憶
        └── <agent-name>/MEMORY.md
```

### 建議的 `.gitignore`

```gitignore
CLAUDE.local.md
.claude/settings.local.json
```

其他 `.claude/` 下的東西**應該**進版控——那是團隊資產。

## 2.3 個人層：`~/.claude/`

### 你會編輯的（設定）

```
~/.claude/
├── CLAUDE.md               跨所有專案的個人偏好
├── settings.json           全域預設設定
├── keybindings.json        自訂快捷鍵
├── rules/                  個人層 rules（先於專案 rules 載入）
├── skills/                 個人技能，每個專案都能用
├── commands/               個人單檔指令
├── agents/                 個人子代理
├── workflows/              個人 workflow 腳本
├── output-styles/          自訂輸出風格
├── themes/                 自訂配色
└── agent-memory/           個人子代理記憶
```

### Claude 自己寫的（記憶）

```
~/.claude/projects/<project>/memory/
├── MEMORY.md          ← 每個 session 開頭載入（前 200 行 / 25KB）
├── debugging.md       ← MEMORY.md 太長時，細節被搬到主題檔
└── api-conventions.md
```

`<project>` 由 git repo 推導，所以**同一個 repo 的所有 worktree 共用一份記憶**。

### 執行期資料（不用管，但要知道它存在）

| 路徑 | 內容 | 清理 |
| --- | --- | --- |
| `projects/<project>/<session>.jsonl` | 完整對話逐字稿：每則訊息、工具呼叫、結果 | 超過 `cleanupPeriodDays`（預設 30 天）自動刪 |
| `projects/<p>/<s>/subagents/` | 子代理的逐字稿 | 隨父 session 一起刪 |
| `projects/<p>/<s>/tool-results/` | 太大而外溢到獨立檔案的工具輸出 | 同上 |
| `file-history/<session>/` | 編輯前的檔案快照，供 `/rewind` 還原 | 保留最近 100 個 checkpoint |
| `shell-snapshots/` | 啟動時擷取的 shell alias/function，Bash 工具會套用 | 正常退出即刪 |
| `plans/` | plan mode 產出的計畫檔 | 依保留期 |
| `debug/` | `--debug` 或 `/debug` 才會寫的日誌 | 依保留期 |
| `backups/` | config 遷移前的 `~/.claude.json` 備份（最多 5 份） | 依保留期 |
| `sessions/` | 每個執行中 session 一個小檔，用來偵測並行與 crash | 退出即刪 |
| `usage-data/` | `/insights` 產生的報表 | 依保留期 |
| `history.jsonl` | **你打過的每一則 prompt**，供上鍵回溯 | 不自動刪 |
| `stats-cache.json` | `/usage` 的 token 與費用統計 | 不自動刪 |
| `cache/changelog.md` | 更新後顯示 release note 用 | 背景刷新 |

### `~/.claude.json`（注意：不在 `.claude/` 裡面）

App 狀態、OAuth session、UI 偏好、**local 與 user scope 的 MCP servers**、
每個專案的信任狀態。這個檔案不該手動大改，用 `claude mcp` / `/config` 操作。

## 2.4 ⚠️ 明文儲存的安全提醒

逐字稿與 prompt 歷史**沒有加密**，只靠 OS 檔案權限保護。
只要工具讀過 `.env`、或指令印出過 token，那個值就寫進了 `projects/<project>/<session>.jsonl`。

降低暴露的三招：

```json
// .claude/settings.json
{
  "cleanupPeriodDays": 7,
  "permissions": {
    "deny": ["Read(./.env)", "Read(./.env.*)", "Read(./secrets/**)"]
  }
}
```

```bash
# 完全不寫逐字稿與歷史
export CLAUDE_CODE_SKIP_PROMPT_HISTORY=1
```

清掉某個專案的所有本機資料：

```bash
claude project purge ~/work/my-repo --dry-run   # 先預覽
claude project purge ~/work/my-repo             # 實際刪除，會再確認一次
```

## 2.5 載入優先序總表

不同機制的衝突規則不一樣，這張表是最常查的：

### CLAUDE.md（**疊加**，不覆蓋）

由廣到窄依序串接，**越後面載入的越靠近 Claude 的注意力**：

```
1. Managed policy CLAUDE.md（企業，無法被排除）
2. ~/.claude/CLAUDE.md（個人）
3. 從檔案系統根往下每一層的 CLAUDE.md
4. 同層的 CLAUDE.local.md（接在該層 CLAUDE.md 之後）
5. 工作目錄的 CLAUDE.md → CLAUDE.local.md（最後讀到）
```

### settings.json（**覆蓋**，高優先序贏）

```
1. Managed settings（企業，不可覆寫）  ← 最高
2. 命令列參數
3. .claude/settings.local.json
4. .claude/settings.json
5. ~/.claude/settings.json             ← 最低
```

`permissions` 是特例：各層規則**合併**，且 `deny` 一律勝過 `allow`。

### Skills / Subagents（**同名覆蓋**）

```
企業 > 個人 (~/.claude/skills/) > 專案 (.claude/skills/)
```

注意方向：**個人的會蓋掉專案的**。另外：

- Skill 也會蓋掉同名的內建 skill（但蓋不掉內建的別名）。
- 外掛的 skill 用 `plugin-name:skill-name` 命名空間，不會衝突。
- 同名時 `skills/` 勝過 `commands/`。
- monorepo 中巢狀的 `.claude/skills/` 兩者都會保留，巢狀那個會顯示成 `apps/web:deploy`。

（子代理的優先序方向相反：`.claude/agents/` 專案 > `~/.claude/agents/` 個人 > 外掛。）

## 2.6 「這個東西該放哪？」決策樹

```
我想加的東西……

├─ 是「事實」，每次都要知道（build 指令、目錄慣例）
│    └→ CLAUDE.md          ※ 控制在 200 行內
│
├─ 是「事實」，但只在碰到某類檔案時才相關
│    └→ .claude/rules/xxx.md 加 paths: frontmatter
│
├─ 是「流程」，我會重複叫它做（部署、發版、review checklist）
│    └→ .claude/skills/xxx/SKILL.md     ※ 用時才載入，平時幾乎不花 context
│
├─ 是「一定要發生」的動作（存檔後 format、commit 前跑測試）
│    └→ settings.json 的 hooks           ※ 這是唯一的硬性保證
│
├─ 是「會讀一大堆檔案」的調查任務
│    └→ .claude/agents/xxx.md 子代理     ※ 用它自己的 context，不污染主線
│
├─ 是「接外部系統」
│    └→ .mcp.json（團隊）或 claude mcp add（個人）
│
└─ 上面做完了想分享給全公司
     └→ 打包成 Plugin
```

**最常見的錯誤**：把多步驟流程塞進 CLAUDE.md。它每個 session 都會被載入、吃 token，
而且指示越長、遵循率越低。搬到 Skill 就好——不用時成本近乎為零。

## 2.7 `/context` 是你的驗證工具

改完設定，永遠用這個確認：

```
/context
```

它會列出：
- **Memory files**：實際載入了哪些 CLAUDE.md / rules
- **Custom Agents**：認得哪些子代理
- 各區塊佔用的 token 數

沒出現在這裡的東西，Claude 就是看不到。設定沒生效時，先跑這個再跑 `/doctor`。
